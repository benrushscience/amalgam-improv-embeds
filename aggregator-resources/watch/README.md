# Watch resource sync

The public page loads `./resources.json`, generated by `../sync_media_resources.py --kind watch`.
The script uses the documented Airtable REST API, follows all pages, preserves record IDs,
and publishes only Public=true / Publication Status=Active records.
Watch additionally requires reviewed `improv_video_type` values, matching the existing page. Paid subscription cards remain independently curated.

Metadata synchronization does not download video or audio. Existing Google Apps Script
proxies continue retrieving recent YouTube uploads and on-demand podcast episodes.
A separate source status indicates synced JSON, a saved fallback, or unavailable data.
Fallback JSON expires 24 hours after retrieval and never silently replaces the source list.

## Local daily automation

The Scheduled Tasks folder contains the matching Python launcher and task registration
script, copied from `../scheduled-tasks/`. The launcher uses the existing Read virtual
environment and encrypted credentials. Keep the repository at its current location.
Each catalog has its own ignored runtime folder, local configuration copy, health.json,
resource-sync.log, and failure alert file. Credentials are not duplicated or published.

Windows runs daily at **3 AM America/Chicago**, one minute after sign-in, and catches
missed runs when available. It allows battery operation, continues when unplugged,
prevents overlapping runs, and retries three times at ten-minute intervals. Like the
existing Read task, it requires the user to be signed in (a locked screen is fine).
It does not wake the computer. It cannot run while the computer is off.

Timestamped reports and latest-report.txt are beside the launcher in a descriptively
named reports folder, retained for 35 days. Detailed logs retain 35 daily rotations.
Health failures are recorded locally with a nonzero exit code; no email is sent.
The daily sync's stale threshold is 36 hours; three consecutive failures also raise
an alert. Use --check-health for a local freshness check without API calls.

## Validation and recovery

Every candidate is validated before publication: required fields, URLs, IDs, duplicate
sources, category/video-type values, numeric ordering, and record counts. Unexpected
count drops over 20% block publication. Absolute floors are in sync-config.example.json;
copy approved configuration changes to the ignored runtime config used by the task.
Do not lower safety floors to bypass an unexplained failure.

GitHub Contents updates use the current blob SHA. Concurrent writes trigger a fresh
read and comparison before retrying. Unchanged content produces no commit, including
no timestamp-only commits. contentUpdatedAt means content changed, not last sync time.
Local health tracks successful unchanged runs. API or validation failures retain the
previous JSON. No unrelated repository edits are staged or published by the sync.

Run from the repository root:

```powershell
# Media resource sync manual run v1
python aggregator-resources/sync_media_resources.py --kind watch
# Add --local-only to fetch/validate without publishing.
python -m unittest discover -s aggregator-resources -p 'test_sync_media_resources.py' -v
```
